# Тест-кейсы для `merge_users.sh`

## 📋 Описание
Скрипт `merge_users.sh` объединяет информацию о пользователях из трёх источников (`users.txt`, `users.json`, `users.csv`) в единый файл `full_users.csv`. Если для пользователя из `users.txt` не хватает данных в других файлах, он пропускается с выводом предупреждения.

---

## 1. Проверка передачи и обработки формата данных

### 1.1 Файл `users.txt`
| № | Сценарий | Тип |
|---|----------|-----|
| 1.1.1 | Один логин на строку | ✅ Позитивный |
| 1.1.2 | Дубликаты в файле | ✅ Позитивный |
| 1.1.3 | Пустые строки | ⚠️ Нейтральный |
| 1.1.4 | Пробелы вокруг логина | ❌ Негативный |
| 1.1.5 | Файл отсутствует | ❌ Негативный |

### 1.2 Файл `users.json`
| № | Сценарий | Тип |
|---|----------|-----|
| 1.2.1 | Валидный JSON-словарь | ✅ Позитивный |
| 1.2.2 | Пустой объект | ✅ Позитивный |
| 1.2.3 | Невалидный JSON | ❌ Негативный |
| 1.2.4 | Массив вместо объекта | ❌ Негативный |
| 1.2.5 | Файл отсутствует | ❌ Негативный |

### 1.3 Файл `users.csv`
| № | Сценарий | Тип |
|---|----------|-----|
| 1.3.1 | Стандартный CSV | ✅ Позитивный |
| 1.3.2 | Другой разделитель | ❌ Негативный |
| 1.3.3 | Отсутствует заголовок | ❌ Негативный |
| 1.3.4 | Пустой файл (или только заголовок) | ✅ Позитивный |
| 1.3.5 | Файл отсутствует | ❌ Негативный |

### 1.4 Передача аргументов скрипту
| № | Сценарий | Тип |
|---|----------|-----|
| 1.4.1 | Корректный вызов | ✅ Позитивный |
| 1.4.2 | Недостаточно аргументов | ❌ Негативный |
| 1.4.3 | Лишние аргументы | ❌ Негативный |
| 1.4.4 | Неверный порядок файлов | ❌ Негативный |

---

## 2. Проверка бизнес-логики объединения

| № | Сценарий | Тип |
|---|----------|-----|
| 2.1 | Полные данные для пользователя | ✅ Позитивный |
| 2.2 | Отсутствует имя в `users.json` | ⚠️ Частичный |
| 2.3 | Отсутствует email в `users.csv` | ⚠️ Частичный |
| 2.4 | Отсутствует и имя, и email | ⚠️ Частичный |
| 2.5 | Лишние данные в источниках | ⚠️ Нейтральный |
| 2.6 | Дубликаты в `users.txt` | ✅ Позитивный |

---

## 3. Проверка граничных значений и спецсимволов

| № | Сценарий | Тип |
|---|----------|-----|
| 3.1 | Имя содержит запятую | ✅ Позитивный |
| 3.2 | Имя содержит кавычки | ✅ Позитивный |
| 3.3 | Email в верхнем/нижнем регистре | ✅ Позитивный |
| 3.4 | Все файлы полностью пустые | ✅ Позитивный |
| 3.5 | Большой объём данных | ✅ Позитивный |
